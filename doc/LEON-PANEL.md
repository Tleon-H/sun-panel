# Leon Panel 说明

Leon Panel 是基于公开的 Sun-Panel **v1.3.0** 源码做的初始定制版。程序内部的数字版本号仍是 `10`，显示名是 `1.3.0+leon.1`。它不是官方 v1.8.1，也不是 v2 测试版。

上游项目仍是 [Sun-Panel](https://github.com/hslr-s/sun-panel)，版权和 MIT 许可证保留在 `LICENSE`。本说明只去掉仓库首页里指向付费功能站的推广段落，没有改许可证，也没有加入或绕过任何授权检查。

## 这一版实际改了什么

- 深色模式下给卡片和搜索框加了浅色描边，设置页里偏灰的字改亮，手机上分组按钮不再只靠鼠标悬停才出现。已经保存的壁纸、颜色和布局不会被清空。
- 搜索仍使用原来的三个搜索引擎。打开“允许搜索栏搜索项目”后，可以用上下键选择当前账号自己的项目，回车打开；没有匹配时会提示“没有匹配的项目”，回车仍跳到搜索引擎。
- 图片地址或在线图标加载失败时，改显示项目名称的一个字，并停止继续请求这一条。文字图标和已经加载成功的自定义图标保持原样。这一版不会自动去抓取网站图标。
- 系统状态卡片离开页面时会停掉定时刷新，未完成的结果也不会再写回。源码里另有一段没有被启动流程调用的后台轮询，补上了停止和避免叠加重试。公开源码里没有复现出官方更新日志之外的连接记录问题。

## 和闭源 v1.8.1 的总体差异

公开仓库里的程序文件停在 v1.3.0。官方文档里的 v1.4 到 v1.8.1 是后来发布版的功能说明，不能从这份源码编译出来。下面的路线只根据 [官方正式版更新日志](https://doc.sun-panel.top/zh_cn/update/update_log.html) 和当前公开源码对照，用来安排以后自己写。不复制闭源程序，不改官方授权，也不保证和官方备份包或 v1.8.1 数据库通用。

官方日志里标成 PRO 的项目，只说明官方那样收费；以后可以用自己的代码做相近能力。这一版没有做这些大功能。

## 1.8.1 功能差异与后续路线

### 搜索配置

- **v1.3 已有：** 可以显示或隐藏搜索栏，可以让搜索栏筛选自己的项目，可以在 Google、百度和必应之间选择，也可以要求用新窗口打开。选择会记在当前账号里。
- **本 PR 增强：** 上下键、回车和没有结果时的提示。没有增加新的搜索引擎。
- **后续待独立开发：** 自定义搜索引擎、排序和搜索栏样式。官方 v1.5.0 开始提供，v1.8.0 又加了排序。
- **复杂度：中。** 保存搜索选择的位置已经有了，但自定义地址的界面和校验要新写，还要保证现在这三个引擎和已保存的选择继续可用。

### 图片管理

- **v1.3 已有：** “上传文件管理”可以查看、复制链接、删除自己上传的图片，也可以把图片设为壁纸。编辑项目时可以手动获取网站图标并保存到服务器。
- **本 PR 增强：** 只处理加载失败后的文字兜底，没有改文件管理。
- **后续待独立开发：** 按图标、壁纸分类，批量上传，以及在各个上传入口直接从图库挑选。官方 v1.8.0 把原来的上传文件管理扩成了图库。
- **复杂度：中。** 文件记录已经按账号分开保存。分类和选择器要接到现有的上传入口，不需要先做一整套新存储。

### 备份恢复

- **v1.3 已有：** 导入导出只覆盖图标和分组的 JSON，不包含壁纸文件、全部账号和数据库。
- **本 PR 增强：** 没有新的备份按钮。下面写了要手工复制备份的目录。
- **后续待独立开发：** 由管理员打包各账号图标、壁纸、配置、数据库文件和自定义样式目录。官方 v1.8.0 的整站备份标成 PRO，且说明不包含单独使用的 MySQL。独立实现不能读取官方备份包。
- **复杂度：高。** 恢复会覆盖现有数据，必须明确告知先备份，并拒绝把官方备份格式或更新的数据库结构当成可以兼容。

### 多账号切换

- **v1.3 已有：** 管理员可以建立多个账号。每个账号的图标、分组和样式分开。换人使用时需要退出后再登录。可以指定一个账号作为不登录也能看到的公开首页，这不是在多个已登录账号之间切换。
- **本 PR 增强：** 没有改登录方式。
- **后续待独立开发：** 在这台浏览器记住多个已登录账号，并在首页切换。官方 v1.6.0 增加了这个功能。
- **复杂度：中。** 账号隔离已经存在。要补的是本机保存多个登录状态和切换按钮，不是另一套权限系统。

### 公共图库

- **v1.3 已有：** 没有。图片属于上传它的那个账号，其他账号不能从这里挑选。
- **本 PR 增强：** 没有。
- **后续待独立开发：** 管理员上传、其他账号只能选用的共享图库。官方 v1.8.0 将其标成 PRO。
- **复杂度：中。** 可以沿用现有上传文件，只增加“管理员上传、其他人可选”的标记，并避免把私人图片一起公开。

### OpenAPI

- **v1.3 已有：** 页面自己用的接口需要登录。没有单独的外部开放接口、接口密钥或公开的接口说明。
- **本 PR 增强：** 没有。
- **后续待独立开发：** 一组用独立凭据调用的稳定接口，例如分组、项目和版本探测。官方从 v1.4.0 起提供 OpenAPI，v1.7.0 和 v1.8.1 又有增补和修复。独立接口不要照搬官方的路径和参数。
- **复杂度：高。** 要单独设计凭据、写入范围、文档和测试。现有登录接口继续只给网页使用。

### Docker 状态及控制

- **v1.3 已有：** 系统状态只看运行这个程序的环境里的 CPU、内存和磁盘。没有容器列表，也不能启动、停止或重启容器。
- **本 PR 增强：** 只清理了上述状态卡片的刷新和离开页面后的停止。不挂载 Docker 套接字，也不控制容器。
- **后续待独立开发：** 查看容器状态，以及是否允许开关容器。官方 v1.5.0 起，非付费版可以看状态，开关是更晚的能力；v1.8.1 又有卡片上的重启。文档要求查看状态时挂载 `/var/run/docker.sock`，这个套接字通常也能控制宿主机上的容器。
- **复杂度：高。** 公开源码没有 Docker 客户端。套接字权限大，查看和开关都要单独做安全边界。这一版明确不做。

## 数据兼容

不要把正在使用的数据库、`conf` 或 `uploads` 直接挂到这一版上试。和官方 v1.8.1、v2 测试版或官方备份包是否通用，目前不知道，本版不承诺兼容。图标 JSON 的配置版本号仍是 `1`，只适合这份 v1.3.0 结构的导入导出。

## 备份范围

试运行前，把下面三项目录完整复制到别处：

- `conf`：配置
- `uploads`：上传的图片
- `database`：默认的 SQLite 数据库

如果还单独使用了 MySQL，或在网站目录里放了自定义 `index.css`、`index.js`，那些也要另备。现有 helper 的 `conf/custom` 不要和这个测试目录混用。

换回旧镜像不会把已经被新程序写过的数据库恢复原状。要回到试运行之前，请用试运行前的那份备份覆盖回去。

## 独立测试容器

在本仓库目录执行，会使用新的 `./leon-test-data` 和主机端口 `13002`：

```sh
docker compose -f docker-compose.leon-test.yml up --build
```

浏览器打开 `http://127.0.0.1:13002`。这个文件只挂载新的 `conf`、`uploads` 和 `database`，不挂载正式数据，也不挂载 Docker 套接字。

## 构建

```sh
pnpm install
pnpm run test:unit
pnpm run type-check
pnpm run build
cd service
go test ./assets ./lib/pollguard
```

前端构建结果在 `dist`。服务端需要先按原项目的方式生成嵌入资源，再编译 `service`。

## 回退

停掉测试容器后，删除或留着 `leon-test-data` 即可，它不影响正式目录。正式环境如果已经用新程序写过数据库，回退时用试运行前的 `conf`、`uploads`、`database` 备份恢复，而不是只换回旧镜像。

# Leon Panel 说明

Leon Panel 是基于公开的 Sun-Panel **v1.3.0** 源码做的独立版本。程序内部的数字版本号仍是 `10`，显示名是 `1.3.0+leon.7`。`10` 是原来用来比较版本的数字，保持不变，这样不会把这一版当成官方更新的程序，也不会当成 1.8.1。显示名里的 `leon.7` 表示在公共图库之外，上传文件管理可以一次选择多张图片，项目图标、壁纸设置和上传文件管理也可以直接从当前账号自己的图片里选用。它不是官方 v1.8.1，也不是 v2 测试版。

上游项目仍是 [Sun-Panel](https://github.com/hslr-s/sun-panel)，版权和 MIT 许可证保留在 `LICENSE`。仓库首页 [README.md](../README.md) 是 Leon Panel 自己的说明，不再沿用上游项目首页。本说明没有改许可证，也没有加入或绕过任何授权检查。

## 这一版实际改了什么

- 深色模式下给卡片和搜索框加了浅色描边，设置页里偏灰的字改亮，手机上分组按钮不再只靠鼠标悬停才出现。已经保存的壁纸、颜色和布局不会被清空。
- 搜索栏仍可筛选当前账号自己的项目。上下键只在确有匹配时移动选择，普通输入、没有匹配时的光标移动，以及输入法组合过程中的回车，都留给输入框。没有匹配时会提示“没有匹配的项目”，回车和放大镜仍使用当前搜索引擎。
- 登录后可以在搜索栏的引擎按钮里增加、修改、删除自己的搜索引擎，并用上移、下移调整顺序，包括 Google、百度和必应的位置。配置记在当前账号的模块设置里。地址只接受 http 或 https。`%s` 表示查询词，查询词会先做 URL 编码再替换全部 `%s`；地址里没有 `%s` 时，编码后的查询词接在末尾。`javascript:`、`data:` 等协议和带尖括号的模板会被拒绝。名称和地址按文字显示，不把它们当成网页或脚本插入。访客不能打开这个编辑面板，也不能保存；公开访问只拿到公开账号当前正在使用的那一个引擎，拿不到该账号列表里其余未选用的地址。没有配置时仍回到 Google、百度和必应，原来保存的当前引擎会继续被选中。
- 图片地址或在线图标加载失败时，改显示项目名称的一个字，并停止继续请求这一条。换成新的图片地址后会重新尝试；旧地址晚到的失败结果不会把新地址标成失败。文字图标和已经加载成功的自定义图标保持原样。这一版不会自动去抓取网站图标。
- 上传文件管理可以按图标、壁纸、未分类筛选，也可以按原来的文件名搜索，并分页查看。文件名里的 `%`、`_` 按字面意思匹配；关键词按字符截断，不会把一个中文切成半个。删掉最后一页的最后一张后，会回到仍有图片的那一页。首页搜索在分组图标从服务器返回后会按当前关键词重新计算。MySQL 的这条搜索语句使用单字符 `!` 转义，避免原来的反斜杠在 MySQL/MariaDB 里变成非法转义；本环境没有 MySQL 服务，这一点只做了 SQL 语句和 SQLite 执行验证，没有连上 MySQL 实测。从项目图标入口上传的新图片记为图标，从壁纸入口上传的记为壁纸，获取网站图标也记为图标，其他新上传记为未分类。升级前已经存在的记录仍是未分类。分类只改数据库里的标记，不移动、不重命名文件，原来的图片链接保持不变。自己的文件列表仍然只包含自己的。访客不能列出或修改别人的文件。没有批量删除。
- 管理员可以在“系统应用”里打开“备份导出”，手动下载一个 zip。普通账号和访客不能导出。压缩包里有本程序 SQLite 数据库的一致性快照、当前配置的上传目录、`conf/conf.ini`，以及存在时的 `web/custom`。清单 `manifest.json` 写有显示版本、时间、每个文件的大小和 SHA-256，并写明没有恢复功能、不兼容官方 1.8.1。使用 MySQL 时不会生成这个包，需要自行备份 MySQL。缺少配置、超过文件或体积上限、没有读取权限、MySQL，以及真正的数据库快照失败，会分别提示，不会都说成快照失败。详见下面的“管理员备份导出”。
- 已登录用户可以在“系统应用 → 切换账号”里登录另一个账号。这台浏览器只记住登录成功后的会话，不保存密码。切换后页面按那个账号自己的图标、文件和设置重新加载。没有登录过的账号不会出现在列表里。访客看不到这个入口。退出当前账号会撤销这一次会话；忘记某个账号只从这台浏览器移除，不删除服务器上的账号。
- 管理员可以在“上传文件管理”里把**自己的**图片设为公共或取消公共。已登录的普通账号可以在“系统应用 → 公共图库”里按图标、壁纸、未分类和文件名浏览这些图片，也可以在项目图标和壁纸设置里选用。选用只把图片地址记到自己的图标或壁纸，不把文件改成自己的。请求里的用户编号不会生效。普通账号和访客不能改公共标记。没有公开的图片不会出现在公共图库，自己的文件列表也不会混进别人的公开图片。已有图片默认不公开。没有批量删除，也没有整站恢复、OpenAPI 或 Docker 套接字控制。
- 上传文件管理可以一次选择多张图片上传。这些图片记为未分类。从图标入口上传的仍记为图标，从壁纸入口上传的仍记为壁纸。不是图片的文件不会保存。新上传的图片仍然默认不公开，也不能在这次上传里指定成别人的文件。批量上传走页面统一的请求封装：数据已经是 `FormData` 时原样交给浏览器，由浏览器写上带 boundary 的 `multipart/form-data`。不会先把字段展平成空对象，也不会改成 JSON。
- 项目图标和壁纸设置里，“从我的图片选择”和“从公共图库选择”并排。我的图片只列出当前账号自己上传的文件，不列出别人的公开图片。公共图库仍然只列出已经标成公共的图片。在上传文件管理里，列表同样只属于当前账号，可以把其中一张设为壁纸，不必重新上传。选用只记录图片地址，不改变文件所属的账号，也不把私人图片公开。
- 系统状态卡片离开页面时会停掉定时刷新，未完成的结果也不会再写回。源码里另有一段没有被启动流程调用的后台轮询，停止时会等到计时器退出，进行中的采样也不会再写入。公开源码里没有复现出官方更新日志之外的连接记录问题。

## 和闭源 v1.8.1 的总体差异

公开仓库里的程序文件停在 v1.3.0。官方文档里的 v1.4 到 v1.8.1 是后来发布版的功能说明，不能从这份源码编译出来。下面的路线只根据 [官方正式版更新日志](https://doc.sun-panel.top/zh_cn/update/update_log.html) 和当前公开源码对照，用来安排以后自己写。不复制闭源程序，不改官方授权，也不保证和官方备份包或 v1.8.1 数据库通用。

官方日志里标成 PRO 的项目，只说明官方那样收费；以后可以用自己的代码做相近能力。这一版没有做这些大功能。

## 1.8.1 功能差异与后续路线

### 搜索配置

- **v1.3 已有：** 可以显示或隐藏搜索栏，可以让搜索栏筛选自己的项目，可以在 Google、百度和必应之间选择，也可以要求用新窗口打开。选择会记在当前账号里。
- **Leon Panel 已实现：** 上下键、回车和没有结果时的提示；登录用户可以增删改自己的搜索引擎并调整顺序。搜索栏的颜色和圆角仍用原来的样式设置，没有另做一套搜索栏外观。官方 v1.5.0 开始提供自定义引擎，v1.8.0 又加了排序；这两项已用独立代码实现，不包含官方的数量限制或付费额度。
- **后续待独立开发：** 搜索栏样式的更多自定义。
- **复杂度：中。** 保存位置沿用原来的账号模块配置。地址校验、旧的三项引擎和已保存的当前选择需要一起保留。

### 图片管理

- **v1.3 已有：** “上传文件管理”可以查看、复制链接、删除自己上传的图片，也可以把图片设为壁纸。编辑项目时可以手动获取网站图标并保存到服务器。
- **本版已实现：** 按图标、壁纸、未分类筛选，按文件名搜索，分页，并按上传入口给新文件一个分类。旧记录保持未分类。可以改自己的分类标记。上传文件管理可以一次选择多张图片，这些图片记为未分类；图标入口仍记为图标，壁纸入口仍记为壁纸。项目图标、壁纸设置和上传文件管理可以从当前账号已经上传的图片里直接选用。自己的列表不包含别人的图片，包括别人已经公开的图片。公共图库已单独实现，见下一节。加载失败后的文字兜底仍然保留。没有批量删除。
- **后续仍不做：** 批量删除，以及让普通账号把私人图片公开给别人。公开仍只能由管理员标记自己的图片。
- **复杂度：中。** 文件记录已经按账号分开保存。分类是原表上的一个新字段，不需要新的存储目录。批量上传沿用原来的多文件接口，并使用和单张相同的格式与分类规则。

### 备份恢复

- **v1.3 已有：** 导入导出只覆盖图标和分组的 JSON，不包含壁纸文件、全部账号和数据库。
- **本版已实现：** 管理员手动下载离线备份包。只导出，不导入，不恢复，不覆盖现有数据。SQLite 使用 `VACUUM INTO` 做成单独的数据库文件，不直接复制可能正在写入的数据库和 WAL。MySQL 明确不支持。官方 v1.8.0 的整站备份标成 PRO，且说明不包含单独使用的 MySQL。这个包不能当作官方备份。
- **后续待独立开发：** 从这份自己的备份包恢复。恢复会覆盖现有数据，必须另做确认，并且不能把官方备份格式或更新的数据库结构当成可以兼容。
- **复杂度：高。** 导出已经限定目录和权限。恢复还要处理覆盖、失败回滚和版本差异，这一版不做。

### 多账号切换

- **v1.3 已有：** 管理员可以建立多个账号。每个账号的图标、分组和样式分开。换人使用时需要退出后再登录。可以指定一个账号作为不登录也能看到的公开首页，这不是在多个已登录账号之间切换。
- **本版已实现：** 在这台浏览器记住多个已登录账号，并在系统应用和登录页切换。官方 v1.6.0 有相近的使用体验；这里用现有登录会话实现，不增加代登录或新的权限。密码不写入浏览器保存的列表。
- **后续仍不做：** 不在多个账号之间合并数据，也不让一个账号读取另一个账号的私人内容。
- **复杂度：中。** 账号隔离已经存在。要补的是本机保存多个登录状态和切换按钮，不是另一套权限系统。

### 公共图库

- **v1.3 已有：** 没有。图片属于上传它的那个账号，其他账号不能从这里挑选。
- **本版已实现：** 管理员把自己的图片标成公共后，其他已登录账号可以浏览，并在图标或壁纸里选用。官方 v1.8.0 的公共图库标成 PRO；这里用现有文件表上的一个标记实现，不复制闭源程序，也不绕过授权。文件仍属于上传者，路径不变。它和“我的图片”分开：公共图库只列出 `is_public`，我的图片只列出当前账号的文件，不把别人的公开图片混进来。
- **后续仍不做：** 不把私人图片自动公开，不让普通账号管理公共标记，也不在账号之间合并图库。
- **复杂度：中。** 沿用原来的上传文件和分类。新增的只是“是否公共”这一个标记。

### OpenAPI

- **v1.3 已有：** 页面自己用的接口需要登录。没有单独的外部开放接口、接口密钥或公开的接口说明。
- **本 PR 增强：** 没有。
- **后续待独立开发：** 一组用独立凭据调用的稳定接口，例如分组、项目和版本探测。官方从 v1.4.0 起提供 OpenAPI，v1.7.0 和 v1.8.1 又有增补和修复。独立接口不要照搬官方的路径和参数。
- **复杂度：高。** 要单独设计凭据、写入范围、文档和测试。现有登录接口继续只给网页使用。

### Docker 状态及控制

- **v1.3 已有：** 系统状态只看运行这个程序的环境里的 CPU、内存和磁盘。没有容器列表，也不能启动、停止或重启容器。
- **本 PR 增强：** 只清理了上述状态卡片的刷新和离开页面后的停止。不挂载 Docker 套接字，也不控制容器。
- **后续待独立开发：** 查看容器状态，以及是否允许开关容器。官方 v1.5.0 起，非付费版可以看状态，开关是更晚的能力；v1.8.1 又有卡片上的重启。文档要求查看状态时挂载 `/var/run/docker.sock`，这个套接字通常也能控制宿主机上的容器。
- **复杂度：高。** 公开源码没有 Docker 客户端。套接字权限大，查看和开关都要单独做安全边界。这一版明确不做。

## 数据兼容

不要把正在使用的数据库、`conf` 或 `uploads` 直接挂到这一版上试。和官方 v1.8.1、v2 测试版或官方备份包是否通用，目前不知道，本版不承诺兼容。图标 JSON 的配置版本号仍是 `1`，只适合这份 v1.3.0 结构的导入导出。

程序启动时会给文件表增加 `category` 字段，已有记录会记为未分类。同一张表还会增加 `is_public`，已有记录默认不公开。文件本身留在原来的目录，链接不变。退回旧程序时，这两个多出来的字段可以留着，旧程序不认识它们，也不会因此删除图片。不要为了退回而手工删掉字段或搬动 `uploads`。如果新程序已经写过其他数据，仍要用试运行前的整份备份恢复，而不是只换镜像。公共图库不是官方 1.8.1 的图库，数据库不承诺和官方版本通用。

## 管理员备份导出

入口在登录后的“系统应用 → 备份导出”，只有管理员看得到。页面上的按钮向 `/api/backup/export` 发送请求，服务器检查当前登录用户是管理员后，把 zip 直接作为这次请求的响应返回。客户端不能指定本机路径，也不能指定要额外打包的目录。压缩包不放进公开的 `uploads`，也没有一个不登录就能打开的固定地址。同一时间只做一份导出；失败、超时或中断时会删除临时文件。单次最多约 2 万个文件、合计 512MB，超过就失败并保持服务继续运行。

打包范围只包括：

- SQLite 数据库。服务器对正在使用的库执行 `VACUUM INTO`，得到一个可以单独打开的数据库文件，再写入压缩包的 `database/database.sqlite`。不会把正在使用的 `database.db`、`-wal`、`-shm` 原样拷进包里。快照会在清单里记录 SQLite 版本和 `integrity_check` 结果。导出过程会短暂锁住数据库，但不会关闭服务。
- 配置里的上传目录，默认是应用目录中的 `uploads`。目录必须留在应用目录内。
- `conf/conf.ini`。
- 如果存在，还有 `web/custom` 里的自定义样式和脚本。

不会打包的内容：符号链接指向的目标、超出应用目录的路径、互相嵌套时重复的目录、MySQL 里的数据。配置如果把上传目录指到应用目录外面，导出会拒绝，而不是跟着读出去。MySQL 会返回明确错误，不会给你一个看起来完整的包。缺少 `conf/conf.ini` 等必需文件、文件数量或体积超过上限、没有读取权限，以及 SQLite 快照本身失败，页面上的提示各自不同。这些失败都不会生成备份包，也不会关闭正在运行的服务。

压缩包里可能有密码哈希、密钥和私人导航。它只适合管理员自己下载后另行保管。页面和 `manifest.json` 都写了这个警告。本版不能从这个包恢复，也不能用它覆盖当前数据。不要把它当成官方 1.8.1 的备份，也不要假设官方程序能打开这份数据库。

SQLite 快照本身是同一时刻的数据库内容，包括已经提交、但还留在 WAL、尚未 checkpoint 的数据。上传目录和 `conf/conf.ini` 是快照完成之后再复制的，所以它们和数据库不是同一个瞬间的事务。导出过程中如果又上传了图片，压缩包里可能出现数据库还没有记录、或记录对应的图片还没复制进去的情况。

试运行前如果还想另外留一份手工副本，可以复制 `conf`、`uploads` 和 `database`。手工复制正在写入的 SQLite 文件不能代替上面的快照。使用 MySQL 时，数据库请用 MySQL 自己的方法备份。

## 重复运行页面检查

`e2e/leon-flows.mjs` 用浏览器打开临时服务，走图标上传、壁纸上传、修改分类后刷新、文件名搜索、分页和备份下载。运行前要自己准备一个只含示例数据的服务，并通过环境变量提供地址和登录信息。脚本不会把登录信息写进输出。

```sh
BASE_URL=http://127.0.0.1:3002 E2E_USERNAME=你的示例账号 E2E_PASSWORD=你的示例密码 CHROME_PATH=/usr/local/bin/google-chrome node e2e/leon-flows.mjs
```

`e2e/own-gallery.mjs` 用同一个临时服务检查批量上传、从自己的图片选为图标和壁纸，以及普通账号看不到别人的私人图片。它需要另外的 `E2E_MEMBER_PASSWORD`。

```sh
BASE_URL=http://127.0.0.1:3002 E2E_USERNAME=你的示例账号 E2E_PASSWORD=你的示例密码 E2E_MEMBER_PASSWORD=临时普通账号密码 CHROME_PATH=/usr/local/bin/google-chrome node e2e/own-gallery.mjs
```

机器上需要能 `import('puppeteer-core')`。这些脚本不在 GitHub Actions 里运行；Actions 跑的是前端单元测试、类型检查、构建和 `go test ./...`。

## 独立测试容器

在本仓库目录执行，会使用新的 `./leon-test-data` 和主机端口 `13002`：

docker compose -f docker-compose.leon-test.yml up --build
```

pnpm run test:unit
pnpm run type-check
pnpm run build
cd service
go test ./assets ./lib/backup ./lib/pollguard ./initialize/systemMonitor ./api/api_v1/system
```

前端构建结果在 `dist`。服务端需要先按原项目的方式生成嵌入资源，再编译 `service`。

## 回退

停掉测试容器后，删除或留着 `leon-test-data` 即可，它不影响正式目录。正式环境如果已经用新程序写过数据库，回退时用试运行前的 `conf`、`uploads`、`database` 备份恢复，而不是只换回旧镜像。
